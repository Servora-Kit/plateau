# 代码复用与职责归属

新增 helper、参数、共享类型或重复流程前，先查找已有定义与调用点。抽取依据是相同契约和共同变化原因，不是出现次数或代码长得相似。

## 判断顺序

- 已有能力能表达需求时直接使用，并确认错误与生命周期契约。
- 已有框架能力不足或存在缺陷时，优先回到能力所属责任方完善；涉及 Servora 时遵循 [协同迭代规则](../plateau/project/boundaries.md#servora-协同迭代)。
- 重复逻辑确实由同一责任方维护时，在该责任边界建立公共实现，调用方保持业务差异。
- 只有一次调用且没有独立含义的 helper 不必抽取；不要为假想的后续扩展引入通用回退和额外配置。
- 两个相同字面量或字段值不一定是同一个概念；只有消费者必须一起改变时才共享定义。
- 生成类型、字段常量与序列化契约由源 Proto／生成器拥有，消费方不能复制私有副本。

## 责任边界

公共规划和组件契约由所属共享层维护，领域校验与业务策略留在应用；归属见[平台边界](../plateau/project/boundaries.md)。目录独立不意味着必须新增公共 package。

审阅变更时检查调用点、错误路径和生成源是否同步。规范只保留一处权威规则，其他正文链接引用，不复制任务历史或上游实现细节。

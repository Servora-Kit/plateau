# 代码复用与职责归属

新增 helper、参数、共享类型或重复流程前，先用 rg 查找已有定义与调用点。抽取依据是相同契约和共同变化原因，不是出现次数或代码长得相似。

## 判断顺序

- 已有能力能表达需求时直接使用，并确认错误与生命周期契约。
- 重复逻辑确实由同一责任方维护时，在该责任边界建立公共实现，调用方保持业务差异。
- 只有一次调用且没有独立含义的 helper 不必抽取；不要为假想的后续扩展引入通用回退和额外配置。
- 两个相同字面量或字段值不一定是同一个概念；只有消费者必须一起改变时才共享定义。
- 生成类型、字段常量与序列化契约由源 Proto／生成器拥有，消费方不能复制私有副本。

## 本项目的例子

[ruleplan](../plateau/codegen/ruleplan.md) 复用两个安全插件的声明、合并与排序；插件仍分别拥有 AuthN/AuthZ 的领域校验。[Servora CRUD](../servora/framework/crud.md) 提供通用资源/列表/映射契约，[service CRUD](../service/backend/crud.md) 展示业务如何组合，tenant scope、etag 和软删策略继续留在业务。

[平台边界](../plateau/project/boundaries.md) 决定复用代码落在哪里。模块专有 internal 目录并不自动成为平台公共能力；不要因为独立目录存在就新建公共 package。

审阅整组变更时检查调用点、错误路径和生成源是否同步；规范只保存一处权威规则，其他正文链接引用。只有确有独立价值的约定才进入通用指南，不把一次任务的历史或上游工具实现细节永久复制到这里。

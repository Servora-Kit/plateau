# 管理服务调用与授权

分层遵循 [共享微服务规范](../service/backend/index.md)，领域归属见 [架构](architecture.md)。

- 通过被管理服务公开契约（IAM `plateau.iam.user.v1.UserService` gRPC、IAM `plateau.iam.client.v1.OAuthClientService` gRPC、Audit `plateau.audit.event.v1.EventService` gRPC）编排调用，不跨服务访问内部 usecase 或数据表；`plateau.admin.audit.v1` 查询链路直接透传 `*auditeventpb.Event` 零重复结构体，分页默认页大小与上限统一委托 `audit.service`；`plateau.admin.client.v1` 直接复用 `plateau.iam.client.v1.OAuthClient` 与 `OAuthClientSecret`，一次性明文客户端密钥全程通过 `servora.redact.v3` 在审计与日志层脱敏。状态转换和身份生命周期留在领域所有者。
- 浏览器侧通过 `security/oidc.RelyingParty`（Authorization Code + PKCE S256 + `nonce` + RFC 9207 `iss` 校验 + HKDF 加密握手 Cookie）接入 IAM 登录：用户在 IAM 主动取消授权（`ErrAccessDenied`）时记录 `OIDC_LOGIN_CANCELLED` 并跳转 `/auth/login?error=login_cancelled`，握手/验签失败记录 `OIDC_LOGIN_FAILED` 并跳转 `/auth/login?error=login_failed`，OpenFGA 无管理权限记录 `SECURITY_ERROR_REASON_PERMISSION_DENIED` 并跳转 `/auth/login?error=access_denied`。`CompleteLogin` 直接返回标准 `plateau.iam.user.v1.User`（含 7 字段 `UserProfile`），并通过 `security/authn/session`（`SaveUser` / `NewUserAuthenticator` / `UserFrom`）在 Admin 自身 PostgreSQL SCS Store（嵌入 `infra/entgo/mixin.HTTPSessionMixin`、由 `security/session.NewPostgres` 构造）维护独立本地会话；`GetSessionResponse` 直接复用 `plateau.iam.user.v1.User`，不重复定义私有身份消息或 `internal/authn` 适配包。退出 Admin 仅销毁本地会话，不联动注销上游 IAM 会话。
- 两层授权各自独立，不可互相替代：
  - 对人：Admin HTTP 入口通过 `security/authz/openfga` 在 `admin:global` 检查操作者的 `access`、`manage_users`、`expunge_users`、`manage_clients`、`read_audit` 权限，并在禁用/删除/永久删除用户前执行防自操作（`SELF_ACTION_FORBIDDEN`）与同级管理员保护（检查目标用户的 `admin` 关系，命中返回 `TARGET_IS_ADMIN`）。
  - 对服务间调用：通过 `servora/transport/client/grpc.Dialer` 挂载 `security/oidc.NewServiceTokenMiddleware`（共享双受众 `[iam, audit]` 的 `client_credentials` 令牌源且立即响应单次请求取消），由接收服务独立验证服务身份与操作权限（见 [授权](../iam/authorization.md) 与 [服务令牌](../iam/oidc.md)）。下游服务凭据、服务权限或网络故障在 Admin 对外统一转换为 `503`（`ADMIN_USER_ERROR_REASON_DOWNSTREAM_UNAVAILABLE` / `ADMIN_CLIENT_ERROR_REASON_DOWNSTREAM_UNAVAILABLE` / `ADMIN_AUDIT_ERROR_REASON_DOWNSTREAM_UNAVAILABLE`），绝不清除有效 Admin 会话或向浏览器误报 `401/403`。
- 冷启动管理员资格通过 `admin.yaml` 的 `bootstrap_admin_email` 以 Ensure-Seed（只增不删）方式幂等写入 `user:<id> admin admin:global`，启动期非阻塞尝试并在 OIDC 登录回调惰性重试。静态配置拥有的资源遵循所属服务的 [启动生命周期](../iam/startup.md)。

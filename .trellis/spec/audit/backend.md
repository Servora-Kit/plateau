# 消费、持久化与查询边界

共通分层遵循 [共享微服务规范](../service/backend/index.md)，不复制旧实现作为新增服务模板。

## 消费与提交

- 兼容 structured JSON 与 binary CloudEvents，校验 `id`、`type`、`source`、`time`；解码或必需属性校验失败按既定坏消息策略记录并提交该条记录。
- 未知事件类型保留通用写入路径；JSON payload 保持原始内容，已注册 protobuf 转为 ProtoJSON，无法识别的内容以包含 content type、schema 与 base64 的 envelope 保存。
- 容量或时间触发批量写入；持久化启用时，仅在写入成功后提交对应记录。准备、追加或发送失败不得提交该批，提交失败须保留诊断信息。
- 可选依赖的禁用路径与持久化成功必须区分；存储未配置时的直接提交不代表事件已落盘。
- 关闭时使用独立、有界的 context 完成最后一次 flush，不复用已取消的消费 context。

## 查询边界

- 查询值使用参数绑定；过滤、事件投影、排序和分页游标须共同审查。
- 旧游标格式不天然绑定过滤、资源范围或授权条件，不得当作通用 CRUD 查询指纹 token；存储未配置时的空结果不证明查询链路可用。

# admin-v1

## 目标

为 Plateau 的唯一平台管理员提供总览与 IAM 用户管理入口。身份、凭据及账号生命周期由 IAM 执行，Admin 提供管理界面与服务调用编排。

配套补齐 IAM 的软删除、恢复与显式永久删除、自助删除、首次改密，并验证 Admin → IAM 的真实服务调用。

## 产品约束

- 前端沿用 Vue Vben Admin（Ant Design Vue）；`app/admin/web` 独立维护 workspace、lockfile 和依赖安装。
- Admin 不另建用户身份，不直接修改 IAM 数据表或复制身份生命周期；仅识别配置指定的唯一管理员，以稳定 IAM 用户 ID 关联。该账号在 IAM 中仍为普通用户身份，Admin 管理资格由 Admin 识别，不转化为 IAM 的特殊用户类别。
- IAM Web 承担本人登录和账号自助管理；Admin 面向唯一平台管理员，不另做个人账号中心。
- Admin 只管理平台共享能力与运维事项，不承载业务运营、租户工作台、组织或订阅管理，也不预设 tenant、租户切换或租户隔离。
- 本文的令牌撤销指 IAM 维护的令牌状态失效、旧 refresh token 不再可用；已签发且由资源服务离线验签的 JWT access token 允许使用至过期，不要求全平台即时拒绝。
- 本期按跨服务请求正常送达的前提设计业务流程，不建设投递可靠性机制；收到明确失败时仍如实返回错误，不提示成功。

## 需求与验收

### 1. 通过 IAM 登录、单独退出 Admin

- [ ] 通过 IAM 完成身份认证，并确认为配置指定的唯一管理员后才能进入工作区、读取受保护数据或执行管理操作；其他 IAM 用户即使已登录也被拒绝。
- [ ] 退出 Admin 只终止 Admin 本地会话，不主动撤销 IAM 或其他应用会话；旧 Admin 会话不能继续访问。再次通过 IAM 认证后仍须检查是否为唯一管理员。
- [ ] 本期 IAM 当前会话登出、封禁、删除、管理重设密码或强制登出均不联动终止 Admin 本地会话；IAM 登出后仍可使用有效的 Admin 会话。Admin 会话由自身退出及有效期管理，并继续执行唯一管理员检查；会话失效后重新通过 IAM 认证。

### 2. 查询 IAM 用户

- [ ] 提供用户列表、详情、分页，以及现有 IAM 领域接口支持的查询条件；显示结果与 IAM 实际数据一致。

### 3. 创建 IAM 用户

- [ ] Admin 先调用 IAM UserService.CreateUser 创建身份与初始凭据，再以返回的用户资源名调用独立的 SendUserVerificationEmail 发送验证邮件。创建接口只创建用户，不发送邮件；账号初始待验证，遵守邮箱唯一性和软删除期间的占用规则，不自动激活或标记已验证。
- [ ] 创建时管理员可选择是否要求用户首次登录修改初始密码，默认开启：Admin 表单默认勾选，IAM 创建接口未收到该选项时按要求改密处理，显式关闭时尊重该选择；选择结果由 IAM 随身份和初始凭据一起持久化。无论选择哪种，仍须满足邮箱验证及账号状态要求；要求改密时按第 11 项完成后才能取得普通业务登录态，不要求时可用管理员设置的密码正常登录。
- [ ] 创建失败时不调用发信接口；创建成功但后续发信失败时，Admin 保留并展示创建接口已返回的身份，提示“账号已创建，但验证邮件发送失败”。本人可从 IAM 现有入口重发；不回滚或重复创建，不自动重试，不提示全部成功或误报账号未创建。
- [ ] 创建事务失败不残留身份、不返回部分完成结果；无权限、邮箱占用或 IAM 拒绝时明确失败。

### 4. 编辑资料、封禁与解禁

- [ ] 可编辑 `name`、`given_name`、`family_name`、`nickname`、`preferred_username`、`picture`、`locale`，并从 IAM 查询到变更。邮箱只读，直接请求后端也不能修改；头像使用 URL，不做文件上传。
- [ ] 封禁对应 IAM 禁用能力；Admin 后端拒绝封禁仍具有 Admin 管理资格的用户，包括操作者本人，直接调用后端也不能绕过。资料校验、状态转换及并发冲突由 IAM 处理。封禁生效，解禁不恢复此前撤销的会话。

### 5. 管理员设置用户密码

- [ ] 有权限的管理员无需目标用户完成邮箱验证、提供旧密码或自助重置凭证即可设置新密码；旧密码失效，邮箱验证事实不变。
- [ ] 设置密码时撤销目标用户全部设备的旧 IAM 登录及 IAM 维护的 OAuth token session、access/refresh token；旧 refresh token 不能继续换取令牌。
- [ ] 没有未完成首次改密要求的账号，可在状态允许时直接使用新密码，不额外要求再改一次；已有首次改密要求不能被清除。用户之后仍可自行改密。

### 6. 强制登出 IAM

- [ ] 提供独立操作，撤销目标用户全部设备的 IAM 登录及 IAM 维护的 OAuth token session、access/refresh token，不修改密码或封禁状态；账号状态允许时可重新登录。
- [ ] 其他用户及独立服务身份不受影响；不承诺同步终止其他应用的本地会话。

### 7. 软删除、恢复与显式永久删除

- [ ] 删除由 IAM 执行，保留用户记录、稳定 ID 和邮箱占用；禁止其登录，已有 IAM 会话及令牌失效。同一邮箱不可重新注册，其他服务的身份引用不改绑。
- [ ] 管理删除与恢复请求只提供用户资源名，不携带 etag 或 allow_missing；操作依据事务内的当前记录和删除状态执行，不检查页面版本。删除不存在或已经软删除的目标返回 NOT_FOUND，不返回未执行删除的成功结果。
- [ ] `ListUsers` 默认排除已删除用户，`show_deleted=true` 时包含未删除与已删除用户；有管理权限的调用方可通过 `UserService.GetUser` 读取已删除用户及其删除信息，物理清理后返回未找到。登录、会话解析和本人资料等认证查询继续排除已删除身份，不因管理查询可见而恢复访问能力。
- [ ] 软删除记录无限期保留，未被永久删除时始终可由有权限的 Admin 操作者通过 IAM UserService 恢复，AccountService 不提供自助恢复。保留原 ID、邮箱、密码、邮箱验证事实及删除前状态：原先可用则可用，原先封禁则仍封禁，待验证则仍须验证。
- [ ] 恢复不复活旧会话或 token，用户须重新登录；不新增首次改密要求，也不清除原有要求。恢复与永久删除并发时不能同时成功或丢失邮箱归属。
- [ ] 仅允许管理员显式通过 `ExpungeUser` 永久删除已软删除用户，要求独立于普通删除的永久删除权限；正常用户不能被直接永久删除。操作前明确提示不可恢复；成功完成清理后才释放邮箱，失败仍占用。同邮箱重新注册取得全新 ID，不继承旧权限或历史归属；并发注册不能提前释放或重复分配邮箱。
- [ ] 永久删除覆盖 IAM 内该用户的身份资料、登录标识、认证凭据、IAM 登录及 OAuth 会话、授权请求与用户令牌记录，不另留历史身份档案。SCS 浏览器会话存储行中的登录引用立即失效，存储行由现有 Store 按 TTL 清理，不要求与 Expunge 同步物理删除。共享 OAuth client 配置、签名密钥、独立服务身份及其令牌不受影响；不跨服务清理业务数据或改绑历史归属。
- [ ] 本期不设固定恢复期，不安排自动清理；`purge_time` 为空表示未安排清理时间。不新增定时扫描器、恢复期或扫描参数配置。

### 8. 唯一管理员识别

- [ ] 本期管理员固定为初始配置指定的一个 IAM 用户，拥有本期全部管理能力，仍受 IAM 领域规则和第 9 项限制；普通 IAM 身份不能获得管理访问，不提供管理员更换功能。
- [ ] Admin 使用独立业务配置文件 `admin.yaml`，通过 `bootstrap_admin_email` 指定 IAM 已有用户为唯一管理员，通常填写与 IAM `bootstrap_user_email` 相同的邮箱；Admin 不另行创建该 IAM 身份。

### 9. Admin 自我保护

- [ ] 后端以可信认证上下文中的用户 ID 判断操作者，拒绝封禁自己或删除自己，且不产生对应变更；绕过页面或伪造操作者 ID 无效。
- [ ] seed 同样受第 4 项及本项限制。本期不提供管理员之间的资料、密码、账号状态或会话管理能力。保护不扩展到 IAM 自助删除或其他受权调用者，不增加跨全部入口的最后管理员协调。

### 10. IAM Web 自助删除账号

- [ ] 用户经 IAM AccountService 验证当前密码后软删除自己的账号，与管理删除复用同一领域命令、无限保留、邮箱占用及会话失效规则，当前浏览器退出 IAM。
- [ ] 目标身份取自可信认证上下文，修改请求不能删除他人；管理和自助入口各自完成认证、权限与确认校验。未认证、密码缺失或错误时不写删除标记、不撤销会话，失败不提示成功。

### 11. IAM Web 首次改密

- [ ] 新 seed 用户必须首次改密；管理创建用户按第 3 项的选择决定是否要求首次改密。IAM 持久化该要求，并为需要改密的用户提供同一 IAM Web 流程，Admin 不承接此交互。
- [ ] 有首次改密要求的用户在登录验证通过后，进入首次改密表单，再次输入初始密码并设置不同的新密码；完成请求提交邮箱、当前密码和新密码，IAM 独立复验账号状态、邮箱验证事实及当前密码。完成前不能取得普通业务登录态或完成 OIDC 授权，直接访问接口、重启或换设备均不能绕过。
- [ ] 成功后清除要求、使初始密码失效并继续原登录/OIDC 流程，下次不再要求；相同密码或改密失败不能清除要求或建立普通登录态。自助注册和无未完成要求的已有账号不新增此流程。
- [ ] 用户经现有邮箱密码重置流程验证有效重置凭证，并成功设置不同于当前密码的新密码时，也视为完成 `UPDATE_PASSWORD`，无需再走首次改密；密码替换与该动作清除共同成功或失败。仅申请重置、凭证无效或过期、密码未改变或重置失败均不能清除要求。管理设密仍按第 5 项保留未完成要求；无该要求的用户沿用既有密码重置行为。

### 12. 服务调用、后端授权与错误处理

- [ ] Admin 使用 Servora gRPC client 调用 IAM；IAM 独立校验目标服务凭据，普通管理动作校验 `manage_users`，`ExpungeUser` 校验独立永久删除权限。拒绝缺失、无效或错误 audience 的凭据，不能通过透传浏览器凭据、自报操作者 metadata 或人的管理资格替代服务授权。
- [ ] Admin 后端检查人的管理权限，菜单和按钮可见性与之保持一致；直接请求不能绕过。
- [ ] 通过 Kratos 结构化 gRPC 错误的 code/reason 区分成功、人的权限不足、领域冲突、服务凭据/权限故障及依赖失败；下游故障不清除人的有效会话，不误报人的登录失效或 401/403，失败不提示完成。
- [ ] 验证请求 deadline/cancel 和 trace 传播；认证失败、权限拒绝、超时及领域冲突可区分，不增加自动重试。
- [ ] 日志能按下游服务、RPC、code/reason 和调用关联定位；各层不重复记录同一请求完成错误。未知内部错误不透出原始信息，原始 cause、密码、token 不返回页面或写入普通请求日志，不泄露密钥。
- [ ] 根据源码、调用契约和实际复现判断是否需要修复 Servora 的通用缺陷、能力缺口或可复用优化，不长期复制框架逻辑或绕过校验。若修改框架，提供框架回归及 Plateau 实际消费证据、记录依赖版本，仅本机 `go.work` 通过不算完成；否则记录现有扩展点的复用路径和联调结果。

IAM token 语义、Actor 映射、Admin 管理资格、OpenFGA 模型及领域规则由 Plateau 负责，不要求为了本期交付而制造框架改动。

### 13. 可复现的本地运行与联调

- [ ] 提供本地启动、检查和验证命令，完成前后端检查、构建及浏览器 → Admin → IAM 的真实联调，覆盖登录、查询、变更、无权限和依赖失败。

### 14. 总览与用户管理菜单

- [ ] 仅提供“总览”和“用户管理”两个一级菜单，不展示 Vben 演示菜单，不额外套只有一个子项的目录。
- [ ] 第 2–7 项用户查询与操作统一归入“用户管理”，包含已删除用户的查看、恢复和显式永久删除入口；详情和操作页面不增加一级菜单。
- [ ] 总览采用轻量首页，展示当前管理员信息和用户管理快捷入口；不提供用户数量、状态分布或趋势统计，不为总览新增统计接口，不使用演示数据冒充真实业务数据。

## 本期不做

- OAuth Client 动态管理（继续静态配置）。
- 审计功能：遵循平台 [审计暂停策略](../../spec/audit/index.md)，不接入审计 middleware，不新增操作审计事件的发送、持久化、查询或管理页面，也不另建替代审计模块；保留第 12 项要求的普通请求日志、错误日志与 trace。Audit 服务重构及 Servora 审计生态迭代均不属于本任务。
- 多管理员、管理员列表及授予／撤销资格的页面和接口、权限管理菜单、自定义角色、只读/编辑等岗位划分、逐项权限配置及独立角色/权限点维护页。多级组织及相关管理能力留待以后单独规划。
- Admin 个人资料或账号安全自助编辑页，以及 IAM 账号中心除自助删除、首次改密外的新功能。
- 创建用户后的密码交付、密码邮件、邀请设密和额外通知，也不把人工交付密码列为验收前置条件；IAM 邮箱验证流程仍保留。
- 对没有未完成首次改密要求的已有账号，在管理重设密码后强制再改一次。
- 用户自助恢复、自助永久删除、未软删除账号的直接永久删除、时间驱动的自动清理，以及 Admin 和其他接入应用的本地会话联动失效；本期不接入 Back-Channel Logout。
- 唯一管理员身份失去可用性后的更换、接管和专门恢复流程，以及跨全部入口保证始终存在可用管理员的全局计数与跨服务协调。
- 重建全局用户身份体系、集中接管所有服务的领域授权、运维脚本/CLI 等独立调用者接入、通用身份委托或全平台 gRPC 重构。
- 请求或登出通知的自动重试、补发、轮询确认、持久化投递任务、outbox、Asynq 或其他队列接入，以及相关故障恢复机制。

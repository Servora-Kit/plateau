# admin-v1

## 目标

为 Plateau 平台管理与运维人员提供统一的 IAM 用户管理和 Admin 管理员资格管理。身份、凭据及账号生命周期由 IAM 执行，Admin 提供管理入口与服务调用编排。

配套补齐 IAM 的删除恢复与到期清理、自助删除、首次改密，并验证 Admin → IAM 的真实服务调用。

## 产品约束

- 前端沿用 Vue Vben Admin（Ant Design Vue）；`app/admin/web` 独立维护 workspace、lockfile 和依赖安装。
- Admin 不另建用户身份，不直接修改 IAM 数据表或复制身份生命周期；管理资格由 Admin 维护，以稳定 IAM 用户 ID 关联。
- IAM Web 承担本人登录和账号自助管理；Admin 面向获授权的管理人员，不另做个人账号中心。
- Admin 只管理平台共享能力与运维事项，不承载业务运营、租户工作台、组织或订阅管理，也不预设 tenant、租户切换或租户隔离。

## 需求与验收

### 1. 通过 IAM 登录、单独退出 Admin

- [ ] 通过 IAM 完成身份认证，并具有 Admin 管理资格后才能进入工作区、读取受保护数据或执行管理操作；普通 IAM 用户即使已登录也被拒绝。
- [ ] 退出 Admin 只终止 Admin 本地会话，不主动撤销 IAM 或其他应用会话；旧 Admin 会话不能继续访问。再次通过 IAM 认证后仍须检查管理资格。
- [ ] 本期 IAM 侧封禁、删除、管理重设密码或强制登出不联动终止 Admin 本地会话；Admin 会话仍受自身有效期及管理资格检查约束。

### 2. 查询 IAM 用户

- [ ] 提供用户列表、详情、分页，以及现有 IAM 领域接口支持的查询条件；显示结果与 IAM 实际数据一致。

### 3. 创建 IAM 用户

- [ ] 管理员经 Admin 调用 IAM UserService 创建身份与初始凭据，遵守邮箱唯一性和软删除期间的占用规则。账号初始待验证，由 IAM 发送验证邮件，不自动激活或标记已验证。
- [ ] 用户满足邮箱验证及账号状态要求后，按第 11 项完成首次改密，才能取得普通业务登录态。
- [ ] 账号提交后发信失败，保留并展示已创建身份，提示“账号已创建，但验证邮件发送失败”；本人可从 IAM 现有入口重发。不自动删除、重复创建、提示全部成功或误报账号未创建。
- [ ] 创建事务失败不残留身份、不返回部分完成结果；无权限、邮箱占用或 IAM 拒绝时明确失败。

### 4. 编辑资料、封禁与解禁

- [ ] 可编辑 `name`、`given_name`、`family_name`、`nickname`、`preferred_username`、`picture`、`locale`，并从 IAM 查询到变更。邮箱只读，直接请求后端也不能修改；头像使用 URL，不做文件上传。
- [ ] 封禁对应 IAM 禁用能力；资料校验、状态转换及并发冲突由 IAM 处理。封禁生效，解禁不恢复此前撤销的会话。

### 5. 管理员设置用户密码

- [ ] 有权限的管理员无需目标用户完成邮箱验证、提供旧密码或自助重置凭证即可设置新密码；旧密码失效，邮箱验证事实不变。
- [ ] 设置密码时撤销目标用户全部设备的旧 IAM 登录及 IAM 维护的 OAuth token session、access/refresh token；旧 refresh token 不能继续换取令牌。
- [ ] 没有未完成首次改密要求的账号，可在状态允许时直接使用新密码，不额外要求再改一次；已有首次改密要求不能被清除。用户之后仍可自行改密。

### 6. 强制登出 IAM

- [ ] 提供独立操作，撤销目标用户全部设备的 IAM 登录及 IAM 维护的 OAuth token session、access/refresh token，不修改密码或封禁状态；账号状态允许时可重新登录。
- [ ] 其他用户及独立服务身份不受影响；不承诺同步终止其他应用的本地会话。

### 7. 软删除、恢复与到期清理

- [ ] 删除由 IAM 执行，保留用户记录、稳定 ID 和邮箱占用；正常查询排除已删除用户，禁止其登录，已有 IAM 会话及令牌失效。同一邮箱不可重新注册，其他服务的身份引用不改绑。
- [ ] 恢复期内仅有权限的 Admin 操作者可通过 IAM UserService 恢复，AccountService 不提供自助恢复。保留原 ID、邮箱、密码、邮箱验证事实及删除前状态：原先可用则可用，原先封禁则仍封禁，待验证则仍须验证。
- [ ] 恢复不复活旧会话或 token，用户须重新登录；不新增首次改密要求，也不清除原有要求。恢复与清理并发时不能同时成功或丢失邮箱归属。
- [ ] 恢复期未到不能清理；到期由 IAM 清理用户及关联身份数据，成功后才释放邮箱，延迟或失败仍占用。同邮箱重新注册取得全新 ID，不继承旧权限或历史归属；重试及并发注册不能提前释放或重复分配邮箱。
- [ ] 恢复期默认 30 天，IAM 通过配置文件及环境变量管理恢复期、清理扫描间隔和每批数量，非法参数明确报错。删除时持久化清理期限，配置调整只影响之后的删除，不重算旧记录。

### 8. 管理 Admin 管理员资格

- [ ] 采用一类统一管理资格，获准者拥有本期全部管理能力，仍受 IAM 领域规则和第 9 项限制；仅拥有 IAM 身份不会自动取得管理资格。
- [ ] 可以查看管理员、选择已有 IAM 用户授予资格及撤销他人资格。撤销不修改 IAM 密码、封禁或删除状态；即使 IAM 登录仍有效，原 Admin 会话也不能继续获得管理访问。
- [ ] “用户管理”“权限管理”为两个一级功能入口；后者直接进入管理员管理页，不套只有一个子项的目录。添加管理员只关联已有身份，不重复创建用户或设置密码；撤销资格不显示为删除账号。
- [ ] Admin 使用独立业务配置文件 `admin.yaml`，通过 `bootstrap_admin_email` 指定 IAM 已有用户为首位管理员，通常填写与 IAM `bootstrap_user_email` 相同的邮箱；Admin 不另行创建该 IAM 身份。

### 9. Admin 自我保护

- [ ] 后端以可信认证上下文中的用户 ID 判断操作者，拒绝封禁自己、删除自己或撤销自己的管理资格，且不产生对应变更；绕过页面或伪造操作者 ID 无效。
- [ ] seed 同样受此限制，不享有永久不可停用的豁免，其他有权限者仍可按领域规则处理它。保护不扩展到 IAM 自助删除、其他受权调用者或多个管理员并发互相操作，不增加全局最后管理员协调。

### 10. IAM Web 自助删除账号

- [ ] 用户经 IAM AccountService 验证当前密码后删除自己的账号，与管理删除复用同一领域命令、恢复期、邮箱占用及会话失效规则，当前浏览器退出 IAM。
- [ ] 目标身份取自可信认证上下文，修改请求不能删除他人；管理和自助入口各自完成认证、权限与确认校验。未认证、密码缺失或错误时不写删除标记/期限、不撤销会话，失败不提示成功。

### 11. IAM Web 首次改密

- [ ] 新 seed 用户及经 UserService.CreateUser 创建的用户，由 IAM 持久化首次改密要求并共用 IAM Web 流程，Admin 不承接此交互。
- [ ] 满足原有账号状态和邮箱验证要求、初始密码验证通过后，必须设置不同的新密码；完成前不能取得普通业务登录态或完成 OIDC 授权，直接访问接口、重启或换设备均不能绕过。
- [ ] 成功后清除要求、使初始密码失效并继续原登录/OIDC 流程，下次不再要求；相同密码或改密失败不能清除要求或建立普通登录态。自助注册和无未完成要求的已有账号不新增此流程。

### 12. 服务调用、后端授权与错误处理

- [ ] Admin 使用 Servora gRPC client 调用 IAM；IAM 独立校验目标服务凭据及 `manage_users` 权限，拒绝缺失、无效或错误 audience 的凭据，不能通过透传浏览器凭据、自报操作者 metadata 或人的管理资格替代服务授权。
- [ ] Admin 后端检查人的管理权限，菜单和按钮可见性与之保持一致；直接请求不能绕过。
- [ ] 通过 Kratos 结构化 gRPC 错误的 code/reason 区分成功、人的权限不足、领域冲突、服务凭据/权限故障及依赖失败；下游故障不清除人的有效会话，不误报人的登录失效或 401/403，失败不提示完成。
- [ ] 验证请求 deadline/cancel 和 trace 传播；认证失败、权限拒绝、超时及领域冲突可区分，不盲目重试结果未知的变更请求。
- [ ] 日志能按下游服务、RPC、code/reason 和调用关联定位；各层不重复记录同一请求完成错误。未知内部错误不透出原始信息，原始 cause、密码、token 不返回页面或写入普通请求日志，不泄露密钥。
- [ ] 根据源码、调用契约和实际复现判断是否需要修复 Servora 的通用缺陷、能力缺口或可复用优化，不长期复制框架逻辑或绕过校验。若修改框架，提供框架回归及 Plateau 实际消费证据、记录依赖版本，仅本机 `go.work` 通过不算完成；否则记录现有扩展点的复用路径和联调结果。

IAM token 语义、Actor 映射、Admin 管理资格、OpenFGA 模型及领域规则由 Plateau 负责，不要求为了本期交付而制造框架改动。

### 13. 可复现的本地运行与联调

- [ ] 提供本地启动、检查和验证命令，完成前后端检查、构建及浏览器 → Admin → IAM 的真实联调，覆盖登录、查询、变更、无权限和依赖失败。

## 本期不做

- OAuth Client 动态管理（继续静态配置）、Audit 查询与管理。
- 自定义角色、只读/编辑等岗位划分、逐项权限配置及独立角色/权限点维护页。
- Admin 个人资料或账号安全自助编辑页，以及 IAM 账号中心除自助删除、首次改密外的新功能。
- 创建用户后的密码交付、密码邮件、邀请设密和额外通知，也不把人工交付密码列为验收前置条件；IAM 邮箱验证流程仍保留。
- 对没有未完成首次改密要求的已有账号，在管理重设密码后强制再改一次。
- 用户自助恢复、绕过恢复期的即时物理删除，以及 Admin 和其他接入应用的本地会话联动失效。
- 跨全部入口保证始终存在可用管理员的全局计数与跨服务协调。
- 重建全局用户身份体系、集中接管所有服务的领域授权、运维脚本/CLI 等独立调用者接入、通用身份委托或全平台 gRPC 重构。

## 未决事项

1. 管理员身份删除、恢复及彻底清理时，Admin 资格关系如何处理。
2. 到期清理需要删除和保留哪些身份关联数据。

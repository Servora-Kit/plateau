## 结论先行

二者都提供面向下游用户的 Web 控制台、项目自发的 API Key、模型/渠道路由和用量结算，不能简单地当成“纯透传反代”。关键区别是**上游凭证与运营重点**：New API 的文档主流程是管理员录入获准使用的模型服务渠道及其 API 凭证，再向组织/用户发行 New API 自己的访问 Key；它以多供应商统一 API、协议适配、权限及用量/成本管理为主。Sub2API 明确将上游 **OAuth/订阅账号** 与 API Key 都视为账号来源，核心模型是把订阅额度作为可调度账户池，对下游发行 API Key，并集成终端用户充值/支付。两者都可对请求做协议转换，但 Sub2API 的 OAuth/客户端会话适配是产品中心能力，New API 更突出 provider channel/adaptor 体系和协议互转。README 中关于可支持协议和支付的描述不代表每个模型、渠道、组合都兼容；应按具体适配器及部署配置验证。

## 请求处理、路由与协议

### New API

- HTTP 入口经过 `controller.Relay`：按请求路径/relay format 校验并解析请求、生成 RelayInfo、预扣计费，再进入重试循环；每次迭代重新执行渠道选择、按所选分组准备计费并调用文本/图片/音频/embedding/rerank/Responses/Gemini/Claude/WebSocket 等对应 handler。错误策略决定停止或继续尝试，并对失败请求退费。[controller/relay.go](https://github.com/QuantumNous/new-api/blob/1a4166d8e8ba9802d2ca56fe8ecf0ed5404e80d5/controller/relay.go)
- 选择器以“用户 Key 的分组 + 模型 + 渠道约束”为条件选 channel；支持优先级/权重、重试、自动组按顺序尝试、会话亲和与 pinning。实现说明 auto-group 下先耗尽组内优先级再进入下一组，并把重试作为优先级索引；请求策略过滤器及 task plugin 还能对 channel 增加约束。[service/channel_select.go](https://github.com/QuantumNous/new-api/blob/1a4166d8e8ba9802d2ca56fe8ecf0ed5404e80d5/service/channel_select.go)、[README capabilities](https://github.com/QuantumNous/new-api/blob/1a4166d8e8ba9802d2ca56fe8ecf0ed5404e80d5/README.md)
- 不只是透明转发：README 列出 OpenAI Chat/Responses、Anthropic Messages、Gemini 等入口；独立 Go `relaykit` 为文本协议 DTO/request-response/streaming 转换提供库，实际支持取决于接口适配器、模型与转换路径。渠道下另有供应商特定 adaptor；故这是**协议网关/translator + relay**，而非所有请求原样透传。[README protocols](https://github.com/QuantumNous/new-api/blob/1a4166d8e8ba9802d2ca56fe8ecf0ed5404e80d5/README.md)、[relaykit README](https://github.com/QuantumNous/new-api/blob/1a4166d8e8ba9802d2ca56fe8ecf0ed5404e80d5/relaykit/README.md)、[relay/channel](https://github.com/QuantumNous/new-api/tree/1a4166d8e8ba9802d2ca56fe8ecf0ed5404e80d5/relay/channel)
- 流式及 WebSocket Realtime/Responses 是 relay format 的分支路径；handler 保留调用流状态供错误/重试和账务处理。协议差异字段不保证完全等价；README 明示转换与 WebSocket 能力取决于 upstream/channel。[controller/relay.go](https://github.com/QuantumNous/new-api/blob/1a4166d8e8ba9802d2ca56fe8ecf0ed5404e80d5/controller/relay.go)、[README](https://github.com/QuantumNous/new-api/blob/1a4166d8e8ba9802d2ca56fe8ecf0ed5404e80d5/README.md)
- 扩展包含 provider adapters 与 JavaScript 异步任务插件；README 将 `plugins/tasks/` 描述为异步任务 API 的扩展点，后端执行任务接口并记录状态/结果。[README extension](https://github.com/QuantumNous/new-api/blob/1a4166d8e8ba9802d2ca56fe8ecf0ed5404e80d5/README.md)、[Dockerfile](https://github.com/QuantumNous/new-api/blob/1a4166d8e8ba9802d2ca56fe8ecf0ed5404e80d5/Dockerfile)

### Sub2API

- Gateway handler 从下游 API Key / auth subject 开始，读取并解析请求体，识别平台、模型、streaming、客户端上下文；预检用户并发槽、额度/订阅并预留在途余额后，生成会话 hash，再向 GatewayService 请求上游账号。代码中 Claude Messages handler 明确体现了这条路径。[gateway_handler.go](https://github.com/Wei-Shaw/sub2api/blob/b8dece9000c68815a5b867ca5a1e6f236e173905/backend/internal/handler/gateway_handler.go)
- 产品及文档明列 **OAuth 与 API Key 两种上游账号类型**；这是与 New API README 主流程最重要的凭证差别：Sub2API 的目标不是只有组织自带官方 API Key。用户创建的下游 API Key 仍是 Sub2API 发行的代理访问凭证，与上游 OAuth/session token 不是一回事。[README_CN 功能/项目概述](https://github.com/Wei-Shaw/sub2api/blob/b8dece9000c68815a5b867ca5a1e6f236e173905/README_CN.md)、[账号管理接口](https://github.com/Wei-Shaw/sub2api/tree/b8dece9000c68815a5b867ca5a1e6f236e173905/backend/internal/handler/admin)
- README 宣称按账号智能选择、粘性会话、并发和 rate limit。实仓可见 account schedulable projection、scheduler cache、gateway routing 和 scheduler outbox/persistent state 源码；Compose 暴露 sticky session waiting、DB fallback、outbox polling/lag/rebuild、slot cleanup 等项。这体现了比“随机选 key”复杂的跨节点调度/状态维护设计。[README_CN](https://github.com/Wei-Shaw/sub2api/blob/b8dece9000c68815a5b867ca5a1e6f236e173905/README_CN.md)、[Compose scheduler settings](https://github.com/Wei-Shaw/sub2api/blob/b8dece9000c68815a5b867ca5a1e6f236e173905/deploy/docker-compose.local.yml)、[repository scheduler cache](https://github.com/Wei-Shaw/sub2api/blob/b8dece9000c68815a5b867ca5a1e6f236e173905/backend/internal/repository/scheduler_cache.go)、[gateway routing integration](https://github.com/Wei-Shaw/sub2api/blob/b8dece9000c68815a5b867ca5a1e6f236e173905/backend/internal/repository/gateway_routing_integration_test.go)
- Handler 构造参数暴露最大账号切换数（默认 Claude 10、Gemini 3）；流式错误处理和账号失败转移是实现重点。代码包含 stream failover、OpenAI credential failover、WebSocket failover/resume 专项源码/测试。应注意：测试文件存在只证明项目覆盖该行为，不等价于验证某次运行成功或覆盖全部提供商。[gateway_handler.go](https://github.com/Wei-Shaw/sub2api/blob/b8dece9000c68815a5b867ca5a1e6f236e173905/backend/internal/handler/gateway_handler.go)、[stream failover test](https://github.com/Wei-Shaw/sub2api/blob/b8dece9000c68815a5b867ca5a1e6f236e173905/backend/internal/handler/gateway_handler_stream_failover_test.go)、[OpenAI failover](https://github.com/Wei-Shaw/sub2api/blob/b8dece9000c68815a5b867ca5a1e6f236e173905/backend/internal/handler/openai_gateway_credential_failover_test.go)
- 多协议入口并包含平台专属的请求处理和兼容分派；源码可见 Claude Messages、OpenAI Chat Completions、OpenAI Responses、Gemini 兼容等独立 handler/路由。它并非单一协议字节级代理。现据已核实文件可确认多种 handler 路径；具体哪些 API 字段做完整互转，仍需逐 provider/协议实现核对，不根据路径命名推断全覆盖。[gateway routes](https://github.com/Wei-Shaw/sub2api/blob/b8dece9000c68815a5b867ca5a1e6f236e173905/backend/internal/server/routes/gateway.go)、[gateway handler](https://github.com/Wei-Shaw/sub2api/blob/b8dece9000c68815a5b867ca5a1e6f236e173905/backend/internal/handler/gateway_handler.go)、[OpenAI Chat handler](https://github.com/Wei-Shaw/sub2api/blob/b8dece9000c68815a5b867ca5a1e6f236e173905/backend/internal/handler/gateway_handler_chat_completions.go)

## 用户、额度、付费与商业化差别

- **New API：** 面向团队/私有网关访问控制；用户 API Key 可配置分组/模型权限，按 token/模型定价与额度使用，支持预付余额/充值码及订阅/套餐等功能。README 说明有 quota、subscriptions、usage logs、expression pricing；`go.mod` 与 controller 有 Stripe、易支付(ePay)、Waffo 等集成依赖/支付控制器。是否启用支付渠道取决于部署配置。项目强调合法授权与公开运营合规，不等于项目授权转售。[README](https://github.com/QuantumNous/new-api/blob/1a4166d8e8ba9802d2ca56fe8ecf0ed5404e80d5/README.md)、[go.mod](https://github.com/QuantumNous/new-api/blob/1a4166d8e8ba9802d2ca56fe8ecf0ed5404e80d5/go.mod)、[subscription/payment controllers](https://github.com/QuantumNous/new-api/tree/1a4166d8e8ba9802d2ca56fe8ecf0ed5404e80d5/controller)
- **Sub2API：** 用户通过发行的 Key 调用上游共享账号/额度，执行 token 用量计量、成本扣减及用户/账号级并发限制；具内置充值支付，README 列出 EasyPay、支付宝官方、微信官方、Stripe。官方支付指南说明支付成功后充值用户余额；同一指南的迁移差异表明确称内置支付“暂不支持”订阅套餐，因此不要把用户充值余额与已实现的定期套餐订阅混为一谈。项目 README 声明没有授权商业化及上游 ToS 风险，使用前需自行审查许可、账户条款和当地法规。[README_CN](https://github.com/Wei-Shaw/sub2api/blob/b8dece9000c68815a5b867ca5a1e6f236e173905/README_CN.md)、[payment guide](https://github.com/Wei-Shaw/sub2api/blob/b8dece9000c68815a5b867ca5a1e6f236e173905/docs/PAYMENT_CN.md)、[gateway billing handler](https://github.com/Wei-Shaw/sub2api/blob/b8dece9000c68815a5b867ca5a1e6f236e173905/backend/internal/handler/gateway_key_billing.go)

## 安全与许可提示

- 上游 OAuth/订阅凭证通常比自有 API Key 承载更强的身份与账户风险；Sub2API 的定位和 README 风险提示明确涉及这类账号。不要把公开 API 入口、不受信任的下游用户与个人订阅账号混同为安全无关的部署配置。

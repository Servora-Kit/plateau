# admin-v1：Admin 后端

## 目标

建立唯一平台管理员使用的 Admin 后端，通过 IAM 完成身份认证，维护独立应用会话，并通过 IAM 公开契约提供用户管理接口。

## 需求来源与范围

来源为 [admin-v1 主 PRD](../10-04-admin-v1/prd.md)。对应父需求的全部约束和验收语义均适用，以下映射只划分职责，不缩减父需求。

涉及 `app/admin/service` 及其 API 契约、生成产物和运行配置。IAM 领域实现归 IAM 子任务，Vben 页面归 Web 子任务；本任务不直接读写 IAM 数据表。

| ID | 父需求 | 本任务交付 |
| --- | --- | --- |
| B1 | §1 | IAM 登录接入、Admin 本地会话、退出与重新认证；IAM 登出不终止有效 Admin 会话。 |
| B2 | §8 | 根据 `admin.yaml` 的 `bootstrap_admin_email` 定位唯一已有 IAM 身份并识别管理员，不创建另一套身份，不提供资格授予、撤销或更换接口。 |
| B3 | §2–7、§14 | 向 Web 提供用户列表、详情、查询与管理操作，以及已删除用户查看、恢复和显式永久删除接口；完整保留 IAM 的状态、唯一性、首次改密和清理语义。 |
| B4 | §4、§9 | 基于可信认证上下文执行自我保护，拒绝管理员自封禁、自删除；不提供管理员之间的管理操作。 |
| B5 | §12 | 检查人的管理访问，使用服务自身凭据调用 IAM；正确处理领域错误、服务凭据故障、依赖失败、deadline/cancel、trace 和日志。 |
| B6 | §13；配合 §14 | 可复现的后端运行、真实 Admin → IAM 调用验证，以及 Web 总览展示当前管理员身份所需的信息。 |

## 验收标准

- [ ] AC-B1（B1、B2）：只有经 IAM 认证的配置指定身份能访问管理接口；其他已登录 IAM 用户、未认证请求或伪造身份均被拒绝；不在 Admin 创建身份或管理额外管理员。
- [ ] AC-B2（B1）：退出 Admin 后旧本地会话不可继续使用，IAM 会话不被主动撤销；IAM 登出后有效 Admin 会话仍可使用；Admin 会话失效后须重新经 IAM 认证并检查管理员身份。
- [ ] AC-B3（B3）：真实 IAM 用户查询及第 3–7 项管理操作可通过 Admin 接口完成，邮箱只读和允许修改的资料字段由后端约束；删除／恢复只向 IAM 传递 name，重复删除的 NOT_FOUND 如实反馈。已删除用户可无限期恢复，或经明确操作永久删除，不能直接永久删除未软删除账号。
- [ ] AC-B4（B3）：保留首次改密选项的未提供、开启、关闭语义。先调用 IAM CreateUser 并保留返回的 User，成功后调用 SendUserVerificationEmail(name)；创建失败不发信，发信失败仍返回已创建身份及准确反馈，不回滚账号或再次创建，不依赖从创建错误中恢复资源名。设密、强制登出、封禁和删除分别调用对应 IAM 契约。
- [ ] AC-B5（B4）：直接请求、伪造操作者信息或绕过页面均不能自封禁、自删除，失败不产生 IAM 变更；seed 遵守相同规则。
- [ ] AC-B6（B5）：真实服务凭据通过 IAM 独立认证授权；缺失、无效、错误 audience 或缺少相应操作权限时失败。永久删除不能仅凭普通管理权限通过，不能借浏览器凭据或操作者 metadata 绕过。
- [ ] AC-B7（B5）：人的权限不足、领域冲突、服务凭据故障及依赖失败可区分；下游故障不清除有效 Admin 会话，也不误报人的登录失效；超时与取消正常传播，不增加自动重试，不泄露敏感信息或重复记录同一请求完成错误。
- [ ] AC-B8（B5、B6）：基于真实调用证明框架扩展点的复用路径；若经确认确需调整 Servora，满足父需求规定的框架回归、真实依赖和 Plateau 消费验证，不能仅以本机 go.work 通过作为完成。
- [ ] AC-B9（B6）：提供后端启动与验证命令，直接通过 Admin HTTP 入口验证登录、查询、变更、无权限和 IAM 依赖失败；配合 Web 完成父任务浏览器链路验收。

## 依赖与交付协作

- 依赖 [IAM 能力补齐](../10-18-admin-v1-iam/prd.md) 的用户管理、身份定位和认证契约；设计可以协同推进，真实管理操作验收必须使用 IAM 实现。
- 本任务负责面向 [Admin Web](../10-18-admin-v1-web/prd.md) 的接口契约，Web 引用同一契约；接口设计由用户逐项确认，不由前后端分别猜测。
- 后端可通过真实 HTTP 与 gRPC 调用独立验证，不要求 Web 页面先完成；父任务整体验收仍需浏览器参与。
- 具体服务布局、会话实现、客户端装配、调用链、错误映射和资源生命周期写入本任务后续设计。

## 约束与不做

- 沿用父任务全部产品约束和排除项；仅负责编排和管理访问，身份状态转换及清理留在 IAM。
- 不新增多管理员、权限管理、动态菜单管理、租户或组织功能，不以 IAM 普通用户身份替代唯一管理员检查。
- 不做审计、跨应用登出通知、自动重试、补发、队列或管理员接管；不为轻量总览新增统计接口。
- IAM 账号自助删除、首次改密交互归 IAM Web；Admin 不另做个人账号中心。

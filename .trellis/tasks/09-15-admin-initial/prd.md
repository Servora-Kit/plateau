# Admin 首期建设

## 目标与用户价值

为 Plateau 平台管理与运维人员提供统一管理应用，首期支持创建 IAM 用户、管理用户资料、强制设置密码、封禁、解禁、带恢复期的软删除及强制登出 IAM，并由 Admin 维护自己的管理权限。同一任务同时补齐 IAM 用户自助删除账号，以及 seed 与管理创建用户共用的首次改密能力；用户身份、凭据、会话、删除恢复及到期清理的领域行为由 IAM 执行。

同一任务附带调整根 AGENTS.md 与各应用前后端的端口配置：IAM、Admin 优先，Example 与 Test 固定放到 10080、10090 段，为后续基础服务留下连续空闲段；不另建端口迁移流程。

本任务同时作为 Servora gRPC client 的真实消费实践，验证带请求上下文、服务身份认证与接收方授权的 Admin → IAM 调用链；确认存在框架通用缺陷、能力缺口或可复用优化需求时，同步迭代 Servora 并验证 Plateau 接入。

## 已确认背景与约束

- Admin 只面向平台管理与运维人员；未来接入业务微服务时，也只管理其平台基础共享能力与运维事项。用户进一步明确 Admin 没有租户概念，租户归业务自身，不在 Admin 模型或界面预设 tenant、租户切换或租户隔离。
- 用户确认前端采用 Vue Vben Admin 的 Ant Design Vue 版本；按最新根 AGENTS，`app/admin/web` 保留 Vben 独立 workspace 和 lockfile，在该目录独立安装依赖，不并入平台根 pnpm workspace。
- 当前没有运维脚本或 CLI 接入需求，首期围绕 Vben 管理界面规划。
- IAM Web 服务用户本人，承担登录和账号自助管理；Admin 面向管理人员，不建立另一套全局用户身份。个人 profile 自助编辑继续使用 IAM，Admin 不复制 go-wind-admin 的个人中心编辑功能；这不取消 R3 中管理员对目标 IAM 用户资料的管理能力。
- IAM 只有部分所需的管理接口。当前仓库已有 Vben Web 骨架与 Just Web 入口，Web 仍使用演示登录。2026-09-16 用户已删除此前复制的 `app/admin/service`，本轮核实目录不存在；实施时按 IAM、Example 和 Trellis 规范重新搭建独立 Admin 后端。Example 作为通用工程与分层参考，IAM 作为认证、会话及启动接线参考，按 Admin 职责选择所需能力；保留现有 Web 和其他工作区改动。现状背景见 [现状调研](research/current-state.md)，配置位置与旧复制树快照见 [端口引用](research/port-layout-migration.md)，领域缺口见 [新增需求核查](research/management-capabilities.md)。
- Admin 自己拥有管理权限结构，以 IAM 用户的稳定 ID 关联操作者；IAM 不为用户保存跨服务通用的“管理员”资格。采用一类统一管理资格，不要求用户预测未来岗位；关系存储和初始化方案见 design。
- go-wind-admin 的用户列表、详情、抽屉和权限入口可作为交互参考，其本地身份、凭据、组织与租户模型不属于 Plateau Admin。用户已确认采用统一管理资格，本期不建设自定义角色；最新菜单讨论采用“用户管理”“权限管理”两个一级入口的安排，权限管理直接管理管理员资格，不增加只有一个子项的“管理权限”层级。

## 首期需求

| 编号 | 需求 |
| --- | --- |
| R1 | 管理人员通过 IAM 完成身份认证，只有具备 Admin 访问资格者才能进入管理工作区并按其权限访问功能；普通 IAM 用户即使登录成功也不能进入该工作区或读取受保护数据。沿用此前已讨论的应用退出边界：退出 Admin 只结束 Admin 本地会话，不主动结束 IAM 登录或其他应用会话。 |
| R2 | 提供 IAM 用户列表与详情查询，支持已有领域接口能够提供的分页和查询条件。 |
| R3 | 管理用户 profile，并提供封禁、解禁操作。可编辑 IAM 现有全部 profile 字段：name、given_name、family_name、nickname、preferred_username、picture、locale；邮箱是登录标识，只读。picture 沿用头像 URL，不新增文件上传。封禁与 IAM 当前禁用能力对应；资料校验和状态转换由 IAM 管理，解禁不恢复已撤销的会话。 |
| R4 | 管理权限在后端执行；页面和按钮可见性与实际权限一致，但不作为唯一的授权检查。 |
| R5 | 用户身份、状态转换和会话撤销规则由 IAM 执行；Admin 不直接改 IAM 数据表，不复制身份生命周期。 |
| R6 | 操作结果清楚区分成功、无权限、领域状态冲突及依赖失败；失败不得显示为已完成。用户进一步要求利用 Kratos 已有的结构化 gRPC 错误传递做好来源映射和日志：按 code/reason 识别 IAM 领域错误与服务凭据/权限故障，不把下游服务故障误报为人的登录失效；保留安全的诊断信息和调用关联，不把原始 cause、密码或 token 返回页面或写入普通请求日志。 |
| R7 | 提供可复现的本地启动和管理操作验证方式，并验证前端、Admin 与 IAM 的实际交互。 |
| R8 | 管理人员可以为目标用户强制设置新密码，首版不要求目标用户完成邮箱验证、不依赖其旧密码或自助重置凭证。IAM 在替换密码时同时撤销该用户全部设备的 IAM 登录及 IAM 维护的 OAuth token session、access/refresh token；不修改邮箱验证事实。对没有未完成首次改密要求的已有账号，新密码直接作为正常密码使用，不额外要求下次登录再改一次；用户之后可自行改密。管理重设密码不能清除 R17 已存在但未完成的首次改密要求。 |
| R9 | 删除采用带恢复期的软删除：在清理前保留用户记录、稳定 ID 及邮箱占用，旧账号不能登录，也不能用同一邮箱注册新账号。共享软删除便利能力按 R22 归 Plateau infra，IAM 拥有删除与关联失效的领域事务；恢复与到期清理分别见 R13、R12。 |
| R10 | 提供强制登出目标用户 IAM 的独立操作，撤销该用户全部设备的 IAM 登录及 IAM 维护的 OAuth token session、access/refresh token；不修改密码或封禁状态，账号状态允许时可以重新登录。此范围不代表已实现所有接入应用本地会话的同步退出。 |
| R11 | Admin 维护操作者资格及其管理权限关系，以稳定 IAM 用户 ID 为引用。用户确认本期采用一类统一的 Admin 管理资格，获准者可以执行当前全部用户管理及管理员资格管理操作，仍受 R18 自我保护和 IAM 领域规则限制；不区分只读、修改等岗位，不提供自定义角色或逐项权限勾选。提供查看管理员、从已有 IAM 用户中授予资格及撤销其他人资格的界面；撤销 Admin 资格不删除或封禁 IAM 身份。首位管理员初始化及权限关系装配由 design 具体化后纳入完整规划评审。 |
| R12 | 恢复期到期后，由 IAM 执行软删除用户及关联身份数据的清理，成功后才释放邮箱供重新注册；新注册必须取得全新用户 ID，不继承旧身份的权限和历史归属。清理延迟或失败时继续占用邮箱，不只凭时间已到就允许重新注册。具体清理数据集合与调度方案在设计中明确。 |
| R13 | 恢复期内仅允许 Admin 中有权限的管理人员通过 IAM UserService 发起恢复；AccountService 不提供用户自助恢复。恢复沿用原用户 ID、邮箱和密码，恢复到删除前的账号状态，邮箱验证事实保持不变：原本可用则恢复可用，原本封禁则仍封禁，原本待邮箱验证则仍须完成验证。恢复不复活已撤销的登录及 token，用户需重新登录，恢复操作不新增改密要求；删除前尚未完成的 R17 首次改密要求仍然保留。恢复期默认 30 天且可配置；管理权限按 R11 的后续方案执行。 |
| R14 | 删除恢复期等生命周期运行参数由 IAM 配置管理。恢复期默认 30 天；计划沿用配置文件和环境变量覆盖方式，清理扫描间隔与每批处理数量也作为可配置的运行参数。用户确认删除时按当次生效配置保存确定的清理时间；配置调整只影响之后发生的删除，不修改已有软删除记录的期限。 |
| R15 | IAM 用户可通过 AccountService 删除自己的账号，纳入同一任务并提供 IAM Web 操作入口。目标身份从可信认证上下文取得，不接受调用方指定任意目标用户。用户确认自助删除前必须重新输入并由 IAM 验证当前密码。UserService 管理删除与 AccountService 自助删除复用同一 IAM 领域删除命令、恢复期、邮箱占用及会话失效规则，各自完成入口认证、权限与确认校验。 |
| R16 | 首期提供管理员创建 IAM 用户的入口，由有权限的操作者经 Admin service 调用 IAM UserService 创建；身份记录与初始凭据由 IAM 管理，不能绕过邮箱唯一性及软删除期间的占用规则。沿用现有邮箱验证流程：创建待验证账号，由 IAM 发送验证邮件，本人完成邮箱验证且账号状态允许后才能登录；管理创建不自动激活账号或标记邮箱已验证。账号已提交但验证邮件发送失败时，保留待验证账号，Admin 明确提示“账号已创建，但验证邮件发送失败”并展示已创建身份；本人通过 IAM 现有入口重发。不自动删除账号、不重复创建，也不显示为全部成功或账号未创建。Admin 创建后不提供密码邮件、邀请、通知或额外交付步骤，也不把管理员另行交付密码列为本任务要求。 |
| R17 | 用户本轮明确 seed 与管理员新建用户复用首次改密逻辑：新创建的 seed 用户和经 UserService.CreateUser 创建的用户，都由 IAM 持久化首次改密要求。账号满足原有状态与邮箱验证要求、初始密码验证通过后，用户必须在 IAM Web 设置自己的新密码，完成前不能取得可用于普通业务访问的 IAM 登录态或继续完成 OIDC 授权。两种创建入口共用 IAM 的状态与改密流程，Admin 不承接该流程。新密码不能与当前临时密码相同；完成后清除首次改密要求，使初始密码失效。管理创建仍遵循 R16 的邮箱验证和创建后不额外交付规则；自助注册及普通已有用户管理重设密码不因此新增首次改密要求。 |
| R18 | 用户确认采用 Admin 入口防误操作：Admin 后端拒绝当前操作者对自己执行封禁、删除或撤销自己的管理资格，以可信认证上下文中的用户 ID 与目标 IAM 用户 ID 比较，不能仅靠页面按钮限制。该规则同样适用于 seed，不将 seed 设为永久不可停用的特殊身份；其他有权限操作者仍可按领域规则处理该用户。保证范围不包含 IAM 自助删除、其他受权调用者或多个管理员并发互相操作后仍有可用管理员，不引入全局最后管理员计数与跨服务协调。 |
| R19 | 当前侧栏采用“用户管理”“权限管理”两个一级入口。“用户管理”操作 IAM 用户资料与生命周期；点击“权限管理”直接进入管理员管理页面，列出现有管理员并提供授予、撤销 Admin 管理资格的操作，不再套一层“管理权限”子菜单。添加管理员是选择已有 IAM 身份并赋权，不在权限页面重复创建身份或设置密码。 |
| R20 | 本任务附带更新根 AGENTS.md 与应用前后端配置：IAM 10000–10009、Admin 10010–10019、Example 10080–10089、Test 10090–10099；每段 +0 HTTP、+1 gRPC、+2 Web，其他位置预留，尚无对应服务的槽位不要求新增进程。10020–10079 留给后续实际新增服务，Audit/CMS 暂不写入应用端口登记表；Audit 未来位于 Admin 之后。本次明确重排取代旧表对应分配，之后不再因新增服务移动 Example/Test。范围为本地监听、Web dev/preview、后端代理、静态 callback 和 Docker 宿主映射，容器内部端口、共享中间件与生产公开端口保持原边界；不另建迁移阶段或扩大为文档治理、Audit 重构。 |
| R21 | 使用 Servora gRPC client 验证 Admin → IAM 的上下文、服务认证、接收方授权和失败传播。根据源码、调用契约与实际复现判定责任；通用框架缺陷、能力缺口或可复用优化可在本任务中先迭代 Servora，再由 Plateau 接入，不在应用侧长期复制框架逻辑或绕过校验。IAM token 语义、Actor 映射、Admin 管理资格、OpenFGA 模型和领域规则仍由 Plateau 负责；不预设必须修改框架，也不扩展为通用身份委托或全平台 gRPC 重构。 |
| R22 | 将 Servora `contrib/db/entgo/mixin` 的软删除便利实现与专属测试迁到 Plateau `infra/entgo/mixin`，更新现有 Example 消费及生成代码，IAM 后续使用平台共享便利层。保留 Servora Ent driver、core/crud 与 Ent List/Clear adapter；其生产代码不依赖该 mixin，但依赖它的测试 schema/live fixture 必须同步解耦，不能反向 import Plateau 或仅删除测试以通过检查。迁移保持已有 Example 行为，不扩大为整个 Ent/CRUD 生态重写。 |

## 验收标准

以下标准在规划评审后转为实施验收清单，不代表已有功能通过验收。

- [ ] AC1（R1、R4）：未登录者不能访问受保护管理数据；普通 IAM 用户登录成功但没有 Admin 访问资格时不能进入管理工作区、读取数据或执行操作，不能仅通过隐藏菜单实现限制。
- [ ] AC2（R2）：有权限的管理人员可查看 IAM 返回的用户列表和详情；分页及查询结果与实际 IAM 数据一致。
- [ ] AC3（R3、R5）：管理人员可编辑 name、given_name、family_name、nickname、preferred_username、picture、locale，并在 IAM 查询到结果；邮箱只读，直接请求后端也不能改写邮箱。资料校验、状态转换与并发冲突行为不被 Admin 绕过，封禁生效，解禁不会恢复旧会话。
- [ ] AC4（R4）：直接请求后端时仍执行权限检查，不能通过绕过页面或按钮限制完成越权操作。
- [ ] AC5（R5、R6）：被管理服务拒绝调用或执行失败时，Admin 返回明确失败结果；成功提示对应真实变更。通过真实 gRPC 验证已知 reason 在链路中可识别，Admin 服务凭据/权限故障不清除人的有效会话、不误返人的 401/403；未知内部错误不透出原始信息。日志能按下游服务、RPC、code/reason 和调用关联定位，验证密码/token 脱敏与各层不重复记录同一请求完成错误。
- [ ] AC6（R7）：按登记的命令完成前后端检查、构建与浏览器联调，覆盖登录、查询、变更、无权限和依赖失败场景。
- [ ] AC7（R8、R5、R17）：有权限的管理人员无需目标用户的邮箱验证、旧密码或自助重置凭证即可设置新密码；旧密码失效，邮箱验证状态不被修改。原本没有未完成首次改密要求的账号可在状态允许时用新密码正常登录，无须再改一次；原本仍有 R17 要求的账号不能借此绕过首次改密。该用户所有旧 IAM 登录和 OAuth 会话、令牌均被撤销，旧 refresh token 不能继续换取令牌；不能只替换密码而遗漏撤销。
- [ ] AC8（R9、R5）：软删除期间用户记录与稳定 ID 仍保留，正常查询排除该用户，旧账号不能登录，已有 IAM 会话及相应令牌失效；同一邮箱不能重新注册，其他服务的身份引用不被改绑。
- [ ] AC9（R10、R5）：强制登出后，该用户全部设备的旧 IAM 登录及 IAM 维护的 OAuth 会话、令牌被撤销；密码和封禁状态不变，账号状态允许时仍可重新登录，其他用户及独立服务身份不受影响。
- [ ] AC10（R11、R4）：仅拥有 IAM 身份不自动取得 Admin 权限；被授予统一管理资格后可以执行本期管理操作，撤销资格后即使 IAM 身份与登录仍有效，也不能继续调用受保护 Admin 接口。撤销不会更改 IAM 密码、封禁或删除状态；不能撤销自己的资格。IAM 仍独立检查 Admin 的服务调用权限，不以人类管理员资格替代服务授权。
- [ ] AC11（R12、R9）：恢复期未到不能清理；到期但尚未清理成功时邮箱仍不可注册；清理成功后同一邮箱可注册为全新用户，旧身份权限不随邮箱继承。清理重试与并发注册不得提前释放或重复分配邮箱。
- [ ] AC12（R13、R5、R17）：有权限的 Admin 操作者通过 UserService 恢复账号后保留原用户 ID、邮箱、密码和邮箱验证事实；删除前可用且邮箱已验证的账号可用原密码重新登录，删除前已封禁的账号仍封禁且不能登录，删除前待验证的账号仍须验证。所有旧会话和 token 仍失效，恢复不新增改密要求，也不清除删除前已有的首次改密要求；普通 IAM 用户不能执行管理恢复，AccountService 没有自助恢复入口。恢复与清理并发时不能同时成功或丢失邮箱归属。
- [ ] AC13（R14、R13）：未覆盖恢复期配置时使用 30 天，非法时长或清理参数在配置校验时明确报错。配置从 30 天改为 7 天并生效后，新删除的账号使用 7 天；已有删除记录的清理时间保持不变。清理任务使用各记录持久化的期限，不按最新配置重算。
- [ ] AC14（R15、R9、R5）：已认证用户从 IAM Web 提交正确的当前密码后，其账号进入与管理删除相同的软删除生命周期，当前浏览器退出 IAM 登录态。未认证、密码缺失或密码错误时不能执行删除，不写删除标记或清理期限，也不撤销会话；修改请求不能删除其他用户。失败不得显示为删除成功，密码不被返回或写入日志。
- [ ] AC15（R16、R4、R5、R9）：有权限的管理员可从 Admin 创建 IAM 用户，成功后能查询到 IAM 中待邮箱验证的新身份；由 IAM 发送验证邮件，验证前不能登录，完成有效邮箱验证且账号状态允许后才可登录。注入账号提交后的发信失败，验证账号保留且只创建一次，Admin 根据明确的部分完成结果展示已创建身份与邮件失败提示，不自动删除、重试创建或提示全部成功；用户可经 IAM 现有重发入口取得验证邮件并继续原流程。创建事务失败时不残留身份，不能返回部分完成结果。无权限、已占用邮箱或 IAM 拒绝时明确失败，不能创建重复身份，也不能使用仍由软删除用户占用的邮箱。密码不得进入日志；Admin 创建后不触发额外的密码交付、邀请或通知流程。
- [ ] AC16（R1、R4）：退出 Admin 后，原 Admin 本地会话不能继续访问受保护管理数据；该操作不主动撤销 IAM 登录或其他应用会话。IAM 登录仍有效时，后续重新进入 Admin 可以再次通过 IAM 完成认证，但仍须通过 Admin 权限检查。
- [ ] AC17（R17、R1、R16）：新 seed 用户与管理创建用户在正确初始密码验证后进入同一套 IAM 首次改密交互；管理创建用户仍须先完成邮箱验证。改密前直接访问受保护接口或发起 OIDC 不能绕过该要求，重启或更换设备不能清除要求。有效新密码提交成功后可继续原登录/OIDC 流程，初始密码失效且下次登录不再要求首次改密；提交相同密码或改密失败不能清除要求或建立普通登录态。自助注册及无未完成要求的已有账号不新增此交互。
- [ ] AC18（R18、R4、R5）：通过 Admin 页面或直接请求 Admin 后端封禁、删除当前操作者本人，或撤销自己的管理资格，均得到明确拒绝，且不产生对应 IAM 状态变更或权限撤销；请求中伪造操作者 ID 不能绕过。对其他用户的操作仍按管理权限与 IAM 领域规则执行，seed 没有永久豁免。IAM 自助删除保持 R15 的既定行为，不因本规则新增 Admin 回查或最后管理员阻断；验收不将该保护宣称为全局始终保留可用管理员。
- [ ] AC19（R19、R11、R5）：两个一级菜单分别直达 IAM 用户管理与管理员资格管理；权限管理无需展开仅有一个子项的目录。可以列出管理员、选择已有 IAM 用户添加资格及撤销他人资格，成功提示对应实际授权关系变更；不会创建重复 IAM 用户或将撤销资格显示为删除账号。
- [ ] AC20（R20、R7）：IAM 保持 10000/10001/10002，Admin 使用 10010/10011（预留）/10012，Example 使用 10080/10081/10082，Test Web 使用 10092（10090/10091 预留）；根 AGENTS 与对应 dev/preview、服务监听、宿主映射、代理、OIDC callback 配置一致。旧 Admin 10050、Example 10030、Test 10040 段不再作为这些应用的默认入口；新配置没有应用间端口冲突。Audit/CMS 不进入新登记表，现有 Audit 运行配置须避开新 Admin 的段；这些配置随本任务联调验证，不单独建立一套迁移验收流程。 |

- [ ] AC21（R21、R4–R7）：真实 Admin → IAM 调用携带目标服务凭据，IAM 独立拒绝缺失/无效/错误 audience 的凭据及无 `manage_users` 权限的服务；不能通过透传浏览器凭据或自报操作者 metadata 绕过。请求 deadline/cancel 和 trace 按既定契约传播，认证失败、权限拒绝、超时及领域冲突得到可区分的结果，不泄露密钥，也不对结果未知的变更请求盲目重试。若修改 Servora，提供框架回归与 Plateau 实际消费两侧证据，记录采用的依赖版本；只有本机 `go.work` 通过不视为接入完成。若现有扩展点足够，则记录复用路径与联调结果，不为满足本项而制造框架改动。

- [ ] AC22（R22、R9）：Plateau Example 的软删除、恢复、默认过滤和显式已删除查询保持原行为，IAM 的领域事务仍按本 PRD 验收；共享便利包及专属单测/生成 Ent 数据库验证归 Plateau。Servora 生产代码、测试夹具和生成引用不再依赖其旧 mixin 包，也不依赖 Plateau；保留的 CRUD 测试继续验证显式查询范围、分页和错误链。迁移后两仓相关测试及独立依赖消费通过，才移除旧包并同步活跃文档；不把本轮迁移前基线测试当作迁移已完成。

## 本期范围之外

- OAuth Client 动态管理：等待 IAM 先提供动态管理能力，当前仍由静态配置管理。
- 为所有已有用户的每次管理重设密码自动新增强制改密要求。新 seed 与管理创建用户的首次改密已由本轮用户意见纳入 R17，不再属于本项排除范围；R8 保留已有账号的既定管理重设行为。
- Admin 创建用户后的密码交付、自动密码邮件、邀请设密与额外通知流程；不将管理员人工交付密码列为验收前置条件。此排除不改变此前确认的 IAM 邮箱验证流程。
- Audit 查询与管理：等待 Audit 重构后明确能力。
- 业务运营流程、业务租户工作台、组织或订阅管理。租户是业务自身的概念，Admin 不建立 tenant 模型或租户切换；不是仅为本期暂缓该模型。
- Admin 内另一套个人 profile/账号安全自助编辑页；用户已有 IAM 账号中心，必要时可从头像菜单导航到 IAM。管理员编辑目标用户资料仍属于 R3。
- 自定义角色、按查看/编辑/封禁等动作分别配置操作者权限，以及独立角色/权限点维护页面；本期采用 R11 的统一 Admin 管理资格。
- IAM 个人账号中心中除本次自助删除、首次改密外的新功能，以及用户自助恢复账号。通知接入应用终止其本地会话的注销协议扩展仍在本期范围之外；IAM 自身的强制登出属于 R10。
- 重建全局用户身份体系或将全部服务的领域授权集中到 Admin。
- 跨全部入口严格保证至少一个可用管理员，以及为此增加的 IAM/Admin 状态协调或全局管理员计数；用户确认本期只做 R18 的 Admin 入口防误操作。
- 运维脚本、CLI 等独立调用者的接入与对应验收；未来有明确需求时另行设计，不永久限制 Admin API 的调用方式。
- 绕过恢复期的即时物理删除入口；恢复期后的 IAM 到期清理已纳入 R12，不在本项排除范围内。

# admin-v1：IAM 能力补齐

## 目标

让 IAM 提供 Admin v1 所需的用户管理能力，并在 IAM Web 完成账号自助删除和首次改密，身份、凭据及生命周期规则继续由 IAM 负责。

## 需求来源与范围

来源为 [admin-v1 主 PRD](../10-04-admin-v1/prd.md)。对应父需求的全部约束和验收语义均适用，以下映射只划分职责，不缩减父需求。

涉及 `app/iam/service`、`app/iam/web` 及其 API 契约和生成产物；共享能力仅在实际需要且方案获确认时调整。Admin 本地会话、管理员识别与管理页面由其他子任务承担。

| ID | 父需求 | 本任务交付 |
| --- | --- | --- |
| I1 | §2、§4、§14；配合 §8 | 用户列表、详情、分页、已有查询条件、允许的资料编辑、封禁与解禁；支持已删除用户查看和恢复入口所需的数据，以及 Admin 按配置定位已有 IAM 身份。 |
| I2 | §3 | 分别提供创建用户和发送验证邮件的 RPC；创建持久化身份、初始凭据与首次改密要求，保持邮箱唯一性和待验证状态；发信结果独立返回，由 Admin 编排。 |
| I3 | §5、§6 | 管理员设置密码及独立强制登出能力，按父需求处理账号状态、首次改密要求、IAM 登录与 OAuth 令牌撤销。 |
| I4 | §7 | 软删除、无限期恢复、管理员显式永久删除和邮箱释放；清理范围严格遵循父需求，不增加期限或扫描配置。 |
| I5 | §10 | IAM Web 自助删除，经当前密码验证，仅作用于可信认证上下文中的本人，与管理删除共用领域规则。 |
| I6 | §11；配合 §3 | 新 seed 必须首次改密，管理创建用户按管理员选择决定要求，并在 IAM Web 登录和 OIDC 授权中执行；本人通过有效邮箱密码重置设置不同新密码也可完成改密要求。 |
| I7 | §12 | IAM 独立验证服务身份及 audience，普通管理动作和永久删除分别检查对应权限；提供可区分的领域错误，遵守调用取消、追踪和敏感信息处理约束。 |
| I8 | §13 | IAM 本地运行与验证说明、真实 API 和 IAM Web 验证，配合 Admin 完成跨服务联调。 |

## 验收标准

- [ ] AC-I1（I1）：列表、详情和已删除用户查询与真实存储一致；仅允许父需求规定的资料变更，邮箱不可被更新；封禁使 IAM 访问失效，解禁不恢复旧会话。Admin 能按配置定位已有身份，不创建替代身份。
- [ ] AC-I2（I2、I6）：CreateUser 只创建账号并返回 User，不发邮件；账号待验证，首次改密选项未提供或开启时要求改密，显式关闭时在验证及状态允许后可直接登录。SendUserVerificationEmail 按用户资源名独立发送验证邮件；失败不回滚已创建账号，调用方保留先前 User 并识别发信阶段。创建事务失败不残留身份；公开自助注册与重发保持原有发信流程。
- [ ] AC-I3（I3）：管理设密无需本人旧密码或重置凭证，旧密码失效、邮箱验证事实不变；设密与强制登出分别遵守父需求，旧 IAM 登录及旧 refresh token 不能继续使用，其他用户和独立服务身份不受影响。
- [ ] AC-I4（I4）：DeleteUser、UndeleteUser 仅接收 name，按事务内当前记录执行，不校验页面 etag；不提供 allow_missing，删除不存在或已软删除目标返回 NOT_FOUND。删除后默认列表和认证查询隐藏、禁止登录、邮箱继续占用，管理 Get 可读；恢复保留原身份、凭据、状态和首次改密要求，旧会话不复活；Expunge 成功后才释放邮箱，同邮箱注册取得新 ID。
- [ ] AC-I5（I4）：永久删除仅接受已软删除目标并要求独立权限；与恢复并发不产生冲突的成功结果。IAM 登录及 OAuth 关联数据随事务清除，旧 SCS cookie 无法解析身份；残余 SCS 存储行按现有 Store TTL 清理。共享客户端、签名密钥、独立服务身份和其他服务数据不受影响；不设置用户清理期限，不运行用户自动扫描。
- [ ] AC-I6（I5）：浏览器中自助删除成功后退出 IAM；未认证、密码缺失或错误、伪造目标身份均不能删除他人或留下删除副作用。
- [ ] AC-I7（I6）：登录验证通过且仍要求改密时，页面清除已输入密码并展示首次改密表单；用户再次输入初始密码，完成请求携带邮箱、当前密码和新密码，由 IAM 独立复验，不依赖待改密凭证或会话。完成前不能建立普通登录态或完成 OIDC 授权；相同密码、失败、重启、换设备均不能绕过；成功后继续原流程，自助注册及无此要求的已有用户行为不变。
- [ ] AC-I8（I7）：缺失、无效、错误 audience 的凭据及无权限服务调用均被拒绝，人的身份或伪造 metadata 不能替代服务授权；领域冲突与依赖故障可区分，不泄露密码、token 或内部 cause。
- [ ] AC-I9（I8）：通过真实 IAM API 与浏览器验证上述路径；向 Admin 提供可复现的联调条件和结果，父任务的完整链路验收仍须由三个子任务共同完成。
- [ ] AC-I10（I6）：持有有效邮箱密码重置凭证的用户成功设置不同于当前密码的新密码后，密码与 `UPDATE_PASSWORD` 的清除共同提交，下次登录不再要求首次改密；仅申请重置、无效或过期凭证、密码未改变及失败不能清除要求。其他动作与管理设密规则不变，无该要求的用户沿用既有重置行为。

## 依赖与交付协作

- 本任务可独立验证 IAM API 和 IAM Web，不依赖 Admin 页面先完成。
- [Admin 后端](../10-18-admin-v1-backend/prd.md) 消费本任务的 IAM 契约；先明确所需契约，再验证真实调用，不以模拟响应作为完成依据。
- [Admin Web](../10-18-admin-v1-web/prd.md) 经 Admin 后端消费 IAM 能力；IAM 自助删除与首次改密页面始终归本任务。
- 接口、调用链和事务合同见 [技术设计](design.md)，逐步改动及业务验收安排见 [实施计划](implement.md)；本任务不承担 Admin 的 OIDC 客户端接入、本地会话及用户管理页面。

## 约束与不做

- 沿用父任务全部产品约束和排除项，尤其是独立应用会话、离线 JWT 自然过期、暂停审计、不新增自动重试或任务队列。
- 不为 IAM 增加 Admin 特殊用户类别或管理员资格管理，不接管 Admin 自我保护，不扩展多级组织、角色或租户能力。
- 不增加密码交付、邀请设密、用户自助恢复或永久删除、未软删除账号的直接永久删除、自动清理、跨服务数据清理或管理员接管功能。
